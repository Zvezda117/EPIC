# 9197 数据处理说明

## 目前各脚本的处理方式

| 脚本 | 数据范围 | 通道数 | 带宽 | 校准 | 输出 |
|------|----------|--------|------|------|------|
| **convert_9197_full_video.py** | 单文件 **完整 ~4.28s** | 128 | **125 MHz**（全基带正频率） | 仅 DC mask，**无时延校准** | 单文件多 gulp npz，供 Python 成视频 |
| **convert_9197_multi_epic_and_stitch.py** | 多文件，每文件 **仅取 1s** | 128 | 125 MHz | CasA 几何时延 + DC mask | 每文件 1 张 EPIC 图，再拼接成 1 张 PNG |
| **convert_9197_1s_epic.py** | 单文件 **仅取 1s** | 128 | 125 MHz | CasA 几何时延 + DC mask | 单 gulp npz 供 EPIC 成 1 张图 |

## 通道与带宽（9197 数据）

- **RF 中心频率**: 1355 MHz  
- **数据**: I/Q 复数，采样率 250 Msps → **基带带宽 250 MHz**（0 ~ 250 MHz）  
- **采样率**: 250 MHz（复采样）  
- **主用脚本 (convert_9197_multi_full_video.py)**  
  - **输出通道数**: 1024  
  - **使用带宽**: **全 250 MHz**（复数 FFT 全部 bin，不再只用前半 125 MHz）  
  - **每通道带宽**: 250 MHz / 1024 ≈ **0.244 MHz**  
  - **FFT**: 每 gulp 10,000,000 采样 → 10,000,000 bin（0~250 MHz）→ 合并为 1024 通道  

## 您的要求 vs 当前实现

- **要求**: 每个文件 **超过 4s 的完整数据**，处理 **多个文件**，**校准后** 处理 **全部数据**，**合成视频**。  
- **当前不足**:  
  - 多文件脚本只用了每文件 **前 1s**，没有用完整 4s+。  
  - 没有“多文件 + 全数据 + 校准 + 视频”一条龙脚本。  

## 新增脚本（满足：全数据 + 多文件 + 校准 + 视频）

- **convert_9197_multi_full_video.py**  
  - 多文件（如 `0 1 2`）  
  - 每文件 **整文件** 读取（~4.28s），**不截断**  
  - **CasA 几何时延校准** + DC mask ±0.5 MHz（基带低/高端）  
  - **1024 通道，全 250 MHz 带宽**（中心 1355 MHz，I/Q 复数 FFT 全部 bin）  
  - 每 40 ms 一帧，多文件按时间顺序拼接为连续帧，再 **合成视频**（GIF；可选 ffmpeg 出 MP4）。  
  - 成图用 **Python 脏图**（EPIC 离线模式每次只处理一个 gulp，无法直接出多帧视频）。

**运行示例：**
```bash
# 单文件全数据 → 视频（约 4.24 s）
python3 scripts/convert_9197_multi_full_video.py 0

# 多文件全数据 → 长视频（文件 0+1+2 ≈ 12.7 s）
python3 scripts/convert_9197_multi_full_video.py 0 1 2
```
输出：`results/multi_full_video/9197_multi_full_calib.gif`，帧在 `results/multi_full_video/frames/`。

## EPIC C++ 对 1024 通道与全带宽的适配

- **constants.h**: `MAX_CHANNELS_4090 = 1024` 已支持；`FS`/`BANDWIDTH` 为原 LWA-SV 硬件用，9197 Python 路径不依赖。
- **option_parser.hpp**: 默认 `--channels` 改为 **1024**；上限仍为 `MAX_CHANNELS_4090`。
- **dummy_packet_gen.hpp**: 从 Python `Get40msGulp` 读取 **nchan、nseqs、chan0** 并写回 metadata，不再写死 128；metadata `nchan` 存 **int**（支持 1024）。
- **py_funcs.hpp**: `Get40msGulp` 增加 `out_chan0` 参数，便于传递 Python 的 chan0。
- **metadata["nchan"]**: 所有生产者与消费者统一为 **int**（原 uint8_t 无法表示 1024）：`packet_processor`、`dummy_packet_gen`、`chan_reducer` 写入 int；`correlator`、`disk_saver`、`epic_live_streamer`、`db_helpers` 使用 `std::get<int>`。
- 使用 Python 提供 gulp 时，npz 的 meta 需包含 `nchan`（如 1024）、`nseqs`、`chan0`，EPIC 会按此配置成像。

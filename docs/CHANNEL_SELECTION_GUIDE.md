# 频率通道数选择指南

## 问题定义

**核心矛盾**：带宽扩大10倍，但通道数不变
```
LWA-SV:  25 MHz ÷ 128通道 = 195 kHz/通道  ✓ 精细
L-band: 250 MHz ÷ 128通道 = 1.95 MHz/通道  ✗ 粗糙
```

---

## Linus式分析

### 第一层：数据结构影响

| 通道数 | 每通道带宽 | FFT点数 | 内存占用 | 计算量 |
|--------|-----------|---------|----------|--------|
| 128 | 1.95 MHz | 25,000 | 基准 | 基准 |
| 256 | 976 kHz | 25,000 | 2× | 2× |
| 512 | 488 kHz | 25,000 | 4× | 4× |
| 1024 | 244 kHz | 25,000 | 8× | 8× |
| 2048 | 122 kHz | 25,000 | 16× | 16× |

**关键点**：
- FFT点数不变（25,000采样点）
- 只是取更多频率bin
- 计算量 ∝ 通道数

### 第二层：科学权衡

#### 场景A：宽带连续谱源
```
目标：脉冲星、超新星遗迹、活动星系核

需求：
- 频谱分辨率要求低
- 更关心灵敏度和时间分辨率

推荐：128-256通道
原因：
✓ 快速处理
✓ 高时间分辨率（100 μs/步）
✓ 足够的频谱覆盖
```

#### 场景B：RFI密集环境
```
现实：地面观测总有RFI

问题：
- 1.95 MHz宽通道：一个RFI污染整个通道
- 488 kHz通道：只污染部分，可以flag

推荐：512-1024通道
原因：
✓ 精细RFI识别
✓ 保留更多干净数据
✓ 提升有效灵敏度20-50%
```

#### 场景C：谱线观测
```
目标：HI 21cm线、OH线、甲醛线

需求：
- 高频谱分辨率（<100 kHz）
- 多普勒速度测量

推荐：2048+通道
原因：
✓ 122 kHz ≈ 27 km/s速度分辨率（@1.4 GHz）
✓ 可分辨星系旋转
✓ 科学必需
```

### 第三层：计算现实

#### 4天线（当前）
```python
# 数据量估算
ntime = 42,865
nchan = [128, 256, 512, 1024]
nbaselines = 6
npol = 2

for nc in nchan:
    vis = ntime * nc * nbaselines * npol
    mem = vis * 8 / 1e9  # complex64
    print(f"{nc}通道: {vis/1e6:.1f}M可见度, {mem:.2f} GB")

结果：
128通道:  65.9M可见度, 0.53 GB  ← 轻松
256通道: 131.8M可见度, 1.05 GB  ← 轻松
512通道: 263.6M可见度, 2.11 GB  ← 可以
1024通道: 527.2M可见度, 4.22 GB  ← 可以
```

**结论**：对4天线，计算不是问题。

#### 256天线（未来）
```
nbaselines = 32,640（256×255/2）

128通道:  358 GB  ← 可以
256通道:  715 GB  ← 需要GPU内存管理
512通道: 1430 GB  ← 需要分块处理
1024通道: 2861 GB  ← 需要认真优化
```

**结论**：扩展到大阵列时，通道数直接影响架构。

## 对比LWA原设计

### 为什么LWA用128通道？

```
LWA-SV设计参数：
- 带宽：25 MHz
- 通道：128
- 每通道：195 kHz

这个选择很聪明：
1. 195 kHz > 大多数RFI带宽（可分辨）
2. 195 kHz < 木星爆发特征尺度（可捕捉）
3. 128是2的幂次，FFT友好
4. 对256天线，128通道计算量可接受
```

### 你应该怎么调整？

```
带宽增加10倍 → 通道数也应该增加

最小：256通道（保持相对分辨率）
推荐：512通道（RFI + 科学平衡）
理想：1024通道（科学级）

不要照搬128！那是针对25 MHz设计的。
```
